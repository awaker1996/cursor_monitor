# 周期明细归零误报「token 明细不可用」修复

- 日期：2026-10-25
- 类型：fix
- 关联文件：src/core/normalizer.ts、scripts/verify-today-percent.ts、README.md

## 背景与根因

弹窗概览间歇性显示「token 明细不可用」。本次实测排查结论与 2026-07-25 那次（TLS 重置导致取数失败）**不是同一问题**：

- 三个接口全部 HTTP 200，事件接口返回完整样本（161/161，`eventsComplete = true`）
- 但本计费周期内的 161 条事件**模型全部是 `grok-bot-automation` / `grok-bot-default`**，无一例外
- 这些模型命中 `EXCLUDED_GROK_BOT_MODELS` 黑名单，在归一化阶段被整体剔除
- 剔除后周期 token 合计为 0，而 `aggregateTokenEvents` 用 `> 0 ? 值 : null` 判定，
  把真实的 0 降级成了 `null` → 概览回退到「token 明细不可用」兜底文案

即：**数据取到了，只是清空后为 0**，但 0 与「取不到」被混为一谈。
同一份快照里「今日」两行显示 `0 tokens`（今日口径早已区分 0/null），「总消耗」那行却显示
「token 明细不可用」，口径分裂。

附带发现：`get-aggregated-usage-events` 在本周期窗口返回的响应体只含 `startDate`、
不含 `aggregations` 字段（HTTP 200），应用据此判定聚合不可用并回退到周期事件聚合——
因此本例中 `aggregatedUsage` 为 `null`，周期 token 只能由事件样本推导。

## 变更摘要

- `resolveCycleTokens` 新增 `noUsageConfirmed` 入参，返回值区分「明细可信」与「取不到」：
  - 服务端整周期聚合有 token → 可信
  - 完整事件样本有 token → 可信
  - 事件样本完整（或聚合有行）但 token 合计为 0，且用量汇总确认本周期没有用量 → 可信的 0
  - 其余情况（样本被分页截断、接口失败、汇总报告了用量却查不到明细）→ 仍为 `null`
- 新增 `summaryReportsNoUsage`：以汇总百分比为准（与 UI「总消耗」口径一致），
  百分比缺失时退到 `used/limit`，且 `limit` 必须已知
- 新增 `cycleTokenDetail`：明细可信时 0 如实上报为 0，否则记 `null`
- `aggregateTokenEvents` 的 `totalTokens` / `apiTokens` / `autoTokens` 改用 `cycleTokenDetail`，
  周期口径与既有今日口径对齐
- `scripts/verify-today-percent.ts` 新增 9 项断言：完整样本归零上报 0、汇总报告用量时仍为
  `null`、分页截断时仍为 `null`、聚合零值行上报 0，以及概览文案层面的断言
  （`0 tokens` 而非 `token 明细不可用`）

## 影响范围

- Cookie Provider 归一化链路的周期 token 三项指标
- 弹窗概览的「总消耗」明细文案、Included Usage 面板周期汇总
- 此前「本周期用量全部来自 grok-bot」的账号，概览由「token 明细不可用」变为「0 tokens」
- 取数失败的真实场景（样本不完整 / 接口失败）行为不变，仍显示「token 明细不可用」
