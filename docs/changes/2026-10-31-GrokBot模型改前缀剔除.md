# Grok Bot 模型改前缀剔除

- 日期：2026-10-31
- 类型：fix
- 关联文件：src/core/normalizer.ts、scripts/verify-included-usage.ts、scripts/verify-today-percent.ts、README.md

## 背景与根因

新增的后台模型 `grok-bot-knowledge-work` 出现在 Included Usage 的 Cursor Models
分类下（例如截图中的 51.3 万 tokens / 0.00%）。原因是黑名单采用**精确名单**：

```ts
const EXCLUDED_GROK_BOT_MODELS = new Set(['grok-bot-automation', 'grok-bot-default']);
```

`isAutoModel` 以 `includes('grok')` 判定第一方模型，因此该变体被归入 Cursor Models；
但它不在精确名单中，剔除逻辑放行，最终作为独立模型行展示。后台侧已按
`grok-bot-*` 家族整体处理，客户端名单落后于上游命名，后续新增变体还会继续泄漏。

## 变更摘要

- `isExcludedGrokBotModel` 改为按前缀判断：
  `model.trim().toLowerCase().startsWith('grok-bot-')`
- 函数名、签名不变，8 处调用点（周期/今日 cost 与 token 汇总、Included Usage
  事件与聚合两条路径）无需改动
- 剔除顺序保持「先计入分母、后跳过明细」不变：bot 的 tokens / cost 仍留在
  Cursor Models 分母中，其份额不会被重分配给 Composer
- IDE 侧模型（如 `grok-4.5-fast-xhigh`）不以 `grok-bot-` 开头，仍正常计入
- 前缀匹配同时覆盖大小写与首尾空格差异
- 回归脚本新增未见过的变体（`grok-bot-knowledge-work`，含大小写/空格形式）：
  - `verify-included-usage.ts`：事件与聚合两条路径均断言该变体被剔除、
    composer 份额仍按含 bot 的分母计算（37.5%）
  - `verify-today-percent.ts`：断言周期 token 与今日百分比不受新变体影响
    （`autoTokens = 8000`、今日 4%、周期 40%）
- README 第 6 章补充说明：应用侧按 `grok-bot-` 前缀剔除家族模型，
  新增变体无需改代码；IDE `grok-4.5-*` 不受影响

## 影响范围

- 所有出现 `grok-bot-*` 新变体的账号：该模型不再作为独立行出现在
  Cursor Models 列表，也不再计入周期/今日的 token 与 cost 分子
- 分母与官方百分比口径不变，Composer 等模型的份额不因剔除而升高
- 仅含 bot 调用的窗口行为不变：聚合回退、周期 0 tokens 语义均沿用原逻辑

- `npx tsx scripts/verify-today-percent.ts`（新增 3 项前缀断言）全部通过
