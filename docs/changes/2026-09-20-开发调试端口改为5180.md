# 开发调试端口改为 5180

## 日期
2026-09-20

## 类型
build, refactor

## 关联文件
- `src/shared/devServer.ts`（新增）— 导出 `DEV_SERVER_PORT = 5180` 与 `devServerUrl(path)`
- `vite.config.ts` — `server.port` 取该常量，并显式设置 `strictPort: true`
- `electron/windows/floatingBall.ts` — 开发态 `loadURL` 改用 `devServerUrl()`
- `electron/windows/flow.ts` — 同上
- `electron/windows/settings.ts` — 同上（含 hash 拼接）
- `electron/windows/subscriptions.ts` — 同上

## 变更摘要
1. 默认端口 5173 与本机其他项目的 dev server 冲突，改为 **5180**
2. 端口收敛为单一来源：新增 `src/shared/devServer.ts`，Vite 配置与四个 Electron 窗口共用同一常量。此前 5173 分别硬编码在 4 个窗口文件里，仅改 Vite 配置会出现「dev server 换端口、窗口仍指向旧端口」的割裂
3. `strictPort: true`：端口被占用时直接失败，而不是静默顺延到下一个端口——静默顺延会让 Electron 窗口加载到错误端口（空白页），显式失败更易排查
4. `src/shared/devServer.ts` 同时被 `tsconfig.json`（渲染层）与 `tsconfig.electron.json`（主进程）包含，两侧共用同一实现

## 影响范围
- 仅影响开发态（`isDev`，即未打包运行时）窗口加载的 URL；打包产物走 `loadFile`，不受影响
- 开发调试入口由 `http://localhost:5173` 变为 `http://localhost:5180`
- 引用 `?raw` 之外的共享模块需注意：该文件是运行时值导入，会被打包进 `dist-electron/main.js`（原有 `src/shared/types.ts` 仅为类型导入）

## 验证
- `npm run dev` 输出 `Local: http://localhost:5180/`，Electron 正常启动并加载窗口内容（日志可见 `[Main] Application started`）
- `npx tsc -p tsconfig.json --noEmit` 通过
- 全仓检索确认已无 `5173` 残留引用
- 端口冲突路径验证：5180 被占用时 `npm run dev` 明确报 `Port 5180 is already in use` 并退出，不会静默换端口
- 测试结束后已释放端口、结束测试用 dev server 与 electron 进程
