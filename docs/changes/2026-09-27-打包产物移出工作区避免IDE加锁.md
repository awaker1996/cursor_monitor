# 打包产物移出工作区，避免 IDE 占用 app.asar 导致构建失败

- 日期：2026-09-27
- 类型：fix, build
- 关联文件：scripts/dist.mjs、package.json（`dist` 脚本说明）、README.md、.cursorignore、.vscode/settings.json

## 问题

停止 `npm run dev` 后立即执行 `npm run dist`，`electron-builder` 清空输出目录时报：

```
remove ...\release-build\win-unpacked\resources\app.asar: The process cannot access the file because it is being used by another process.
ERR_ELECTRON_BUILDER_CANNOT_EXECUTE
```

经 Windows Restart Manager 定位，被占用的只有 `app.asar` 一个文件，占用者并非残留的应用实例，而是
**打开了本项目的 Electron 系编辑器/IDE**（实测为 MiniMax Code 与 OpenChamber）在工作区索引时打开了该文件并长期持有句柄。

- 被占用的文件在占用期间**既不能删除、也不能重命名**，因此“重试删除”“换一个目录再打包”都只能治标；
- 旧脚本的 `release-build` 兜底目录同样位于工作区内，同样会被 IDE 加锁，于是报错从 `release` 转移到了 `release-build`。

## 变更摘要

- 重写 `scripts/dist.mjs`：
  - 打包前结束残留的已打包应用与 dev Electron 实例（按进程名、可执行文件路径、命令行三重匹配，不误伤编辑器）；
  - 将 `electron-builder` 的输出目录改为工作区**之外**（默认 `%LOCALAPPDATA%\CursorTokenMonitor\dist`，可用环境变量 `CURSOR_MONITOR_DIST_DIR` 覆盖），IDE 不会索引该目录，从根上消除加锁；
  - 打包完成后仅把安装包、`*.blockmap`、`latest.yml` 等发布物拷回 `release/`，并在未被占用时刷新 `release/win-unpacked`；
  - 目录清空、文件覆盖均带重试，用于吸收杀毒软件/索引器的短时占用；
  - 顺带清理旧版遗留的 `release-build` 目录。
- 新增 `.cursorignore` 与 `.vscode/settings.json`（`search.exclude`、`files.watcherExclude`），阻止编辑器索引构建产物。
- 更新 README「执行打包 / 打包前注意事项」，说明产物发布位置与占用时的处理方式。

## 影响范围

- `npm run dist` 不再依赖能否删除工作区内的旧产物，构建稳定通过；
- `release/` 仍作为稳定的产物发布目录（安装包、便携版、`latest.yml`）；
- `release/win-unpacked` 在编辑器仍占用 `app.asar` 时会被跳过刷新并给出提示；关闭/重载编辑器后再执行一次即可刷新，安装包不受影响；
- 未打包应用运行时的目录结构、安装流程均不受影响。

## 验证

- 复现占用场景（MiniMax Code / OpenChamber 打开本项目）后执行 `npm run dist`：typecheck、vite build、electron-builder 全部通过，安装包与 `latest.yml` 成功发布；
- 外部输出目录 `%LOCALAPPDATA%\CursorTokenMonitor\dist\win-unpacked` 内容完整（含 exe 与 app.asar）；
- 不再出现 `ERR_ELECTRON_BUILDER_CANNOT_EXECUTE`；仅在被编辑器占用的 `release/win-unpacked` 上给出可操作提示。
