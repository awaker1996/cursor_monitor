# token 明细不可用排查修复

- 日期：2026-07-25
- 类型：fix
- 关联文件：src/core/providers/CookieProvider.ts、src/core/snapshotMerge.ts、src/core/providers/ProviderManager.ts、scripts/verify-today-percent.ts、scripts/diagnose-token-detail.ts、scripts/diagnose-events-retry.ts、scripts/diagnose-endpoint-stability.ts

## 背景与根因

弹窗概览间歇性显示「token 明细不可用」。实测排查结论：

- 明细文案兜底于 `metrics.totalTokens == null`（`buildDashboardSummary`），其值依赖 `get-filtered-usage-events`（周期事件）与 `get-aggregated-usage-events`（服务端聚合）两个 POST 接口
- 离线聚合逻辑回归全部通过，排除归一化 bug
- 线上实测：Cookie 有效（JWT 未过期）、接口通时返回正常（events 1660 条 / aggregations 17 行）；但对 `cursor.com` 的 TLS 连接**间歇性 ECONNRESET**（握手前被断开，同一分钟内忽好忽坏）
- `www.cursor.com` 备用域名对该 Cookie 恒定 401 not_authenticated，fallback 形同虚设
- 应用端每接口每轮**只请求一次**，一旦碰上 TLS 重置，该轮 cycleEvents 与 aggregatedUsage 双双为 null → totalTokens 算不出 → UI 显示「token 明细不可用」

## 变更摘要

- `CookieProvider` 新增 `fetchWithNetworkRetry`：网络级抛错（TLS 重置等）最多重试 2 次、递增短退避（400ms×n）；HTTP 4xx/5xx 响应不重试；调用方 abort 立即终止。应用于 summary GET、事件分页 POST、聚合 POST 全部请求
- `snapshotMerge` 新增 `mergeCycleTokensFromCache`：同一计费周期内，本轮刷新丢失周期 token 明细（totalTokens/apiTokens/autoTokens）时沿用上轮缓存值并标记 stale，百分比等新鲜字段不受影响
- `ProviderManager.fetch` 在 `mergeTodayMetricsFromCache` 之后串接 `mergeCycleTokensFromCache`
- `scripts/verify-today-percent.ts` 补充 `mergeCycleTokensFromCache` 回归断言（回填、跨周期不合并、新鲜数据不动）
- 新增诊断脚本：`diagnose-token-detail.ts`（三接口全链路探测）、`diagnose-events-retry.ts`（重试探测）、`diagnose-endpoint-stability.ts`（成功率采样），复测网络状况用

## 影响范围

- Cookie Provider 全部对 cursor.com 的请求（网络失败时最多多耗约 1.2s 重试时间）
- 弹窗概览 token 明细、Included Usage 数据在网络抖动时的可用性
