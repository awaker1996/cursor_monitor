## 变更摘要

### 标题简化

- `settings.html` 第 6 行 `<title>` 由 `Cursor Token - 设置` 改为 `设置`；Electron 渲染层 ready 后会用 `<title>` 覆盖 `BrowserWindow` 创建时传入的 `title: '设置界面'`，最终窗口标题栏、任务栏悬浮预览、Alt-Tab 缩略图统一显示短名。

### 「智能体」Tab

- 设置窗口顶部 TabBar 重排为「智能体 / 订阅 / 流水 / 其他」四项，**默认 Tab 改为「智能体」**；通过 `settings.html#agent` 或托盘跳转参数直接定位。
- 数据源唯一：`%APPDATA%/Cursor/User/{globalStorage,workspaceStorage/<id>}/state.vscdb`，仅以 `readonly: true, fileMustExist: true` 打开，与 Cursor WAL 写锁不冲突；workspace 按 mtime 倒序只看前 5 个。

### 真实数据结构（重要）

排查时通过 `scripts/inspect-cursor-schema.ts` 等脚本确认 Cursor state.vscdb 的实际形态：

- 整个数据库的有效数据集中在 **一张表 `cursorDiskKV(key, value)`**，所有 Composer / Bubble / Agent 数据都按 key 前缀分散存储：
  - `composerData:<composerId>` — 主记录（含 `name`、`lastUpdatedAt`、`fullConversationHeadersOnly[]`）
  - `bubbleId:<composerId>:<bubbleId>` — 单条 bubble（`type:1`=用户，`type:2`=AI，含 `text`、`thinking{text,signature}`、`createdAt`）
  - `ofsContent:<bubbleId>:<fileURI>` — Agent 用 `read_file` 读到的文件内容快照
  - `codeBlockPartialInlineDiffFates:<bubbleId>:<fileURI>` — Agent 编辑文件的 diff fate
- `composerHeaders` 在本机实测为 0 行的空表（v3 schema 已废弃）。
- `ItemTable` 是 VSCode 工作区 KV，与 Composer 无关。
- **Bubble 顶层 `toolResults` / `suggestedCodeBlocks` / `interpreterResults` / `editTrailContexts` 都是空数组**，实际工具数据通过侧表 `ofsContent` / `codeBlockPartialInlineDiffFates` 关联。

旧版 parser 错误地把 `cursorDiskKV` 当作多张独立表（`composerData` / `cursorDiskKV` / `agentConversation` …）做表名探测，所以 Tab 一直空。本版基于真实数据结构重写：先 `WHERE key LIKE 'composerData:%'` 拉主记录，再按 `lastUpdatedAt DESC` 选最近活跃 composer，取 `fullConversationHeadersOnly` 顺序，逐个 `WHERE key LIKE 'bubbleId:<composerId>:%'` 拿 bubble，再 `WHERE key LIKE 'ofsContent:<bubbleId>:%'` 和 `WHERE key LIKE 'codeBlockPartialInlineDiffFates:<bubbleId>:%'` 反查工具调用。

### 解析层

- Sub-agent（`task-tool_*` / `task-call_*`）被排除，不进入用户级 trace。
- 同 bubble 的 tool_call / tool_result 自动归属到对应 thinking / assistant 后。
- 主路径 `parseLatestTrace` 返回空时退化到 `parseLatestBubbleFallback`：扫描全部 `bubbleId:*` 行找最近一个有 thinking / text 的 bubble。
- 时间线展示：thinking / tool_call / tool_result / assistant / user 五类 turn 各配一种配色 + 标签；tool_call 折叠参数 JSON，tool_result 折叠结果 JSON，长文本提供「展开全文」。

### 错误分级

- `NOT_INSTALLED`（蓝 info）/ `LOCKED`（黄 warn，轮询不中断）/ `SCHEMA_UNKNOWN`（红 error，调试折叠展示命中表）/ `NO_DATA`（蓝 info）/ `INTERNAL`（红 error）。
- 调试折叠：显示数据库路径、类型、命中表清单、最近 turn 时间，并提供「复制诊断信息」（只含路径与字段名，不含用户输入文本）。
- 2s 轮询由主进程发起，渲染层可在 Tab 上点「暂停轮询」忽略推送（不停止主进程读库，保持热路径简单）；连续 5 次同 code 错误后拉长到 30s。
- 隐私：本特性只读取本机 Cursor 数据并在内存中渲染，不发起任何网络回传。

### 自动化

- `scripts/verify-agent-trace.ts` 用 `new Database(':memory:')` 构造一张 `cursorDiskKV` 表，覆盖完整解析、sub-agent 排除、空库、bubble 缺失、不含 cursorDiskKV 表、fallback 路径等场景，**25 个断言全部通过**。
- `npm run typecheck` 通过（electron + renderer 两套 tsconfig）。
