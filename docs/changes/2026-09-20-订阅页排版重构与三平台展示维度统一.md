## 变更摘要

### 1. provider 切换改为卡片式
- 由「灰底轨道 + 白底胶囊」改为三张独立卡片：名称 + 健康点 + 一行关键摘要（Cursor 显示周期用量百分比、Command Code 显示剩余额度、DeepSeek 显示余额与币种）
- 激活卡为蓝描边 + 光晕，未激活为浅灰描边；摘要行取自缓存，随刷新更新
- 切换按钮不再包在白色卡片里（避免卡片套卡片），直接落在页面背景上
- 保留 `role="tablist"` / `role="tab"` / `aria-selected`，健康点 `aria-hidden`，`title` 仍承载健康状态说明

### 2. 三平台统一为同一套骨架
每个 provider 一张面板，内部固定四段，缺数据的段整块不渲染：

1. **概览**：状态徽标 + 主数值 + 单位 + 副信息
2. **关键指标**：三列等宽网格（三平台均为 3 项）
3. **周期与账户**：键值行
4. **用量明细**：表格 + 底部「合计」行（DeepSeek 的月份选择器移到该段标题右侧）

各平台映射：

| 段 | Cursor | Command Code | DeepSeek |
|---|---|---|---|
| 概览 | 周期总用量 %、来源、周期 | 剩余额度 $、月度/购买/赠送 | 余额 + 币种、充值/赠送 |
| 关键指标 | Cursor Models %、Other Models %、明细模型数 | 当期消耗、请求数、Tokens | 本月 Token、本月请求、缓存命中率 |
| 周期与账户 | 计费周期、数据来源、凭据状态 | 套餐、计费周期、账号、统计口径 | 账户状态、各币种余额构成、查询月份 |
| 用量明细 | 两张模型表（含分类合计） | 输入/输出 Tokens、请求数、成功率、平均单次成本（含合计） | 模型表（含合计）+ 零用量脚注 |

- 限额计量条固定在「周期与账户」之后，仅 Command Code 有
- 原先独立的「账户额度 / 用量限额 / 月度用量」三张卡片合并进同一面板，消除了同一页面三种区块语言的割裂

### 3. Command Code 补充用量明细与合计
- 接口 `usage/summary` 实际还返回 `totalTokensIn` / `totalTokensOut` / `completedCount` / `failedCount` / `successRate` / `averageCost` / `periodBasis`，此前只解析了 `totalCost` / `totalCount` / `totalTokens`，本次全部解析并展示
- 新增「用量明细」表：输入 Tokens、输出 Tokens、请求数（成功/失败拆分）、成功率、平均单次成本，底部「合计」行给出总成本 + 总 Tokens
- 该接口**没有按模型或按天的明细**（只有计费周期汇总），因此明细按指标维度拆分；「统计口径」行显示接口返回的 `periodBasis`

### 4. DeepSeek 合计改为当月合计并新增合计行
- 合计取自接口返回的全部模型（含零用量模型）之和，与表格是否隐藏零行无关，保证口径与平台一致
- 新增「合计」行：Token、输出、命中率、请求四列合计；命中率按输入 token 加权
- 零用量模型不再占表格行（此前一律列出全量模型目录，多为 0），改为脚注「另有 N 个模型本期无用量，未在表中列出」
- 月份选择器从独立区块移入「用量明细」段标题右侧，月份与缓存不一致时仍给出提示（原行为保留）

### 5. 其他一致性调整
- Token 数字统一为万/亿格式（`formatIncludedUsageTokens`）：此前 DeepSeek 用 k/M、Cursor 用万/亿，同一页面两套写法；请求数保持千分位精确值
- 数值列宽由 46px 改为 80px：原宽度放不下「6947.4万」，导致相邻两列数字贴在一起
- 订阅页引入 `.page-shell--subscriptions { gap: 16px }`，区块间距与「其他」分区一致（此前卡片相互紧贴，两条 1px 边框叠在一起）
- 移除重构后不再使用的样式：`.provider-switcher*`、`.sub-panel-head*`、`.sub-divider`

## 影响范围
- 订阅页视觉与结构整体变化：单面板四段骨架取代三张独立卡片
- **订阅缓存结构变化**：`CACHE_VERSION` 提升到 2，旧缓存会被丢弃（首次打开需重新查询一次，之后仍走缓存）
- Token 数字显示格式由 k/M 改为万/亿；零用量模型不再出现在表格中
- 查询与刷新策略未改：进入订阅分区刷新全部已配置提供方、页内切换 provider 只读缓存、自动刷间隔跟随「其他」分区配置
- 凭据配置区未改；Cursor / 自动刷新的既有行为未改

## 验证
- **只读探测真实接口**（临时脚本，用本机凭据库凭据，仅 GET，不打印凭据内容；验证后已删除）：
  - Command Code：`whoami` / `credits` / `subscriptions` / `usage/summary` 均 200，确认 summary 的可用字段清单，且 `since` 参数对结果无影响（`periodBasis: billing-period`）
  - DeepSeek：`usage/amount` 必须同时给 month + year（只给 year 或空参数返回 422），响应含 `total`（按模型）与 `days`（按天）；`total` 中多数模型为 0，印证零用量过滤的必要性
- `npx tsc -p tsconfig.json --noEmit` 通过；`tsconfig.electron.json` 仅剩改动前就存在的 `ProviderManager.ts` 两条未使用声明报错
- 临时壳页（注入 `electronAPI` mock，数据取自上述真实响应）+ headless Chrome 按 1118×689 与 1118×1250 逐 provider 截图核对：
  - 三平台均为四段骨架；切换卡片与面板标题一致；合计行、零用量脚注、月份选择器、限额计量条位置均正确
  - 修复项复验：数值列宽调整后 token 与百分比不再粘连
- 过程中排除一处假象：headless 虚拟时间下 CSS transition 会停在中间帧，导致「高亮卡片与面板不一致」的错误观感；用 DOM 诊断（卡片 className + 面板标题 + 焦点）确认代码正确，并在禁用 transition 后复现正常
- 人工验证（待用户执行）：在实际窗口中切换三个 provider，确认四段结构、合计行与卡片摘要；首次打开会因缓存版本提升重新查询一次
