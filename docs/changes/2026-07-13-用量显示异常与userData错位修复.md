# 用量显示异常与 userData 错位修复

- 日期：2026-07-13
- 类型：fix
- 关联文件：electron/main.ts、src/core/providers/CookieProvider.ts、src/core/providers/ProviderManager.ts、src/core/normalizer.ts、src/core/snapshotMerge.ts、src/shared/types.ts、scripts/verify-cookie-summary.ts、scripts/verify-included-usage.ts、scripts/verify-today-percent.ts

## 变更摘要

- 根因 1：Windows 下 Electron 在 `app.setPath('cache', …)` 后会把 `userData` 重映射到 `runtime/Cache/<AppName>`，设置与快照写入错位目录；空 metrics 快照被当成成功结果展示为全部 `--`
- 根因 2：Cookie `usage-summary` 只要 HTTP 200 即接受，遗留 `/api/usage` 或空 JSON 也会进入 normalize，百分比全为 null，却仍保存并覆盖缓存
- 根因 3：今日百分比在 cost/token 双口径间切换，且周期分母来自可能被截断的 events，导致「今日 API / First-party models」反复横跳
- 根因 4：events 拉取失败时整包保存「周期有值、今日 null」快照，覆盖含今日值的缓存
- 启动时固定 canonical `userData`，并在设置 cache 后再次 pin；从错位目录迁移可用的 settings/snapshot/icon
- 增加 `isUsableCookieSummary`：拒绝 billing-only、空 plan、legacy `/api/usage` 等无效响应
- 今日百分比固定为费用口径：`(今日费用 / 周期费用) × 周期权威百分比`；周期费用优先 aggregated，完整零用量显示 `0%`
- today/cycle events 使用独立 AbortController 与 `eventsComplete` 完整性标记
- 新增 `mergeTodayMetricsFromCache`：同日同账单周期内，今日数据不可信时保留上次可信今日值并标记 stale
- `isEmptyUsageSnapshot` 与迁移判定统一为「主百分比或 quota 至少一项可用」

## 影响范围

- 启动路径与本地缓存位置恢复到 `%AppData%/<AppName>/`
- Cookie 刷新不再把无效汇总当成成功；无效时显示上一份可用缓存并标记 stale
- 今日 API / First-party models 百分比稳定，不再在个位数与十位数间横跳
- events 超时或分页截断时，今日指标回显缓存而非 `--`
