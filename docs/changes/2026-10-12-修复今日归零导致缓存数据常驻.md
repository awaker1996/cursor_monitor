# 修复今日用量归零导致「缓存数据」常驻

## 日期
2026-10-12

## 类型
fix

## 关联文件
- `src/core/normalizer.ts`
- `scripts/verify-today-percent.ts`

## 变更摘要
- `aggregateTokenEvents` 中今日四个字段（`apiTodayTokens` / `autoTodayTokens` / `apiTodayUsed` / `autoTodayUsed`）的取值由 `> 0 ? 值 : null` 改为按 `todayComplete` 判定：今日事件完整时上报真实值（含 0），仅在今日样本不完整或缺失时才为 `null`
- 修复连锁故障：今日真实用量为 0 时被写成 `null`，`mergeTodayMetricsFromCache` 将其读作「算不出今日指标」，于是从内存中的上一次快照回填旧的今日 token/used 并把 `stale` 置为 `true`；下一轮刷新重复同样操作，`stale` 永不自愈，状态 pill 常驻「缓存数据」

## 影响范围
- 今日用量为 0 时不再显示「缓存数据」；今日 token 明细由「—」变为「0 tokens」，与 0.00% 的百分比口径一致
- 典型触发场景：当日只有被剔除的 `grok-bot-*` 后台调用（默认且现在恒为剔除），今日实际用量为 0
- 今日数据不完整（`eventsComplete === false`）或事件接口整体失败时，四个字段仍为 `null`，沿用既有的缓存回填与 `stale` 标记行为，`verify-today-percent.ts` 的 partial / unreliable 用例不受影响
- 周期指标、Included Usage、订阅链路均不受影响
- 已被污染的 `snapshot-cache.json` 会在修复后的下一轮刷新自愈（不再回填旧值）
