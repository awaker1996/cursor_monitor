## 变更摘要

背景：批次 B 建令牌、批次 C 补体验之后，本批次做「加分项」——噪点质感、电池省电、大屏适配、导航指示器、首帧闪烁。D6（Win11 真 acrylic）按方案不排期。

### D5 首帧主题闪烁修复

- `index.html` / `settings.html` 的 `</head>` 前各加一段内联脚本：读 `localStorage['ui-style']`，命中 `aurora` / `calm` 就先写 `document.documentElement.dataset.uiStyle`。
- `src/renderer/uiStyle.ts`：`applyUiStyle()` 在写 `data-ui-style` 的同时镜像写一份到 localStorage（键名导出为 `UI_STYLE_STORAGE_KEY`，与内联脚本约定一致；写入失败静默降级）。
- **真源仍是 IPC**：`useUiStyleSync()` 逻辑未改，挂载后按设置覆盖纠偏。localStorage 只是「上次用过的风格」的缓存，不一致时首拍错主题、随后自动纠正——远好于现状（calm 用户每次开窗必闪深色）。

> 与原计划的一处偏差：计划写「在 `SettingsStore.ts` 保存时镜像写 localStorage」，但 `SettingsStore` 跑在主进程（`import { app } from 'electron'`），没有 localStorage。改为在渲染层的 `applyUiStyle` 里写——两窗任一窗启动都会刷新这份副本，效果等价。

### D3 设置窗大屏适配

- `.settings-panel` 加 `margin: 0 auto`：720px 上限不变，但窗口拉宽后内容居中，不再整块挤在左侧。
- 新增 `@media (min-width: 1280px)`：上限放宽到 860px（2K/4K 下留白收窄）。
- 窄窗（minWidth 720）布局不变；`.settings-panel--fill`（关于页）未覆写 `max-width`，行为与改动前一致。

### D1 极光玻璃噪点纹理

- 新增令牌 `--glass-noise`：`feTurbulence` 生成的 140×140 灰度噪点 SVG，base64 内嵌（`type='fractalNoise'`、`baseFrequency='0.9'`、`numOctaves='3'` + `feColorMatrix saturate 0`，rect 透明度 0.055）。纸面主题置为 `none`。
- 叠加方式：作为**首层 `background-image`** 写进 `.floating-ball__panel` 与 `.set-card` 的 `background` 列表（calm 下这两个类都有整块覆写，天然不掺噪点）。

> 与原计划的两处偏差（均为有意的简化）：
> 1. **没加 wrapper 元素**。计划提出 `::before` / `::after` 已被占用时改用内部 wrapper，但那要动 `SettingsPanel.tsx` 与全部 `.set-card` 用法，侵入面过大。改为直接并入现有 `background` 列表——零新增 DOM、零布局影响。
> 2. **噪点落在基础层**（极光画布 `::before` 之下），不是 `mix-blend-mode: overlay` 的顶层膜。原因是极光画布本身就是大面积半透明径向渐变，噪点在下也能透出来，读感是「细微颗粒」而非「一层雾」。想要更明显的胶片颗粒感，后续可再考虑加 wrapper。

- 静态零动画成本，`prefers-reduced-motion` 天然兼容；仅极光主题生效。

### D4 侧导航滑移指示器

- `SettingsNav.tsx`：`.settings-nav__list` 内新增 `.settings-nav__thumb`（放在一个 `li.settings-nav__thumb-slot` 里，保持 `ul` 子元素合法），用 **ref 实测激活项的 `offsetTop / offsetLeft / offsetWidth / offsetHeight`** 写内联样式。
- 过渡：`top/left/width/height` 走 `var(--dur-slow) var(--ease-spring)`，`opacity` 走 `var(--dur-base)`。
- 视觉：极光 = 斜向高光渐变 + 顶部内高光 + 蓝外发光（与 `panel-view-switch__thumb` 同语言）；纸面 = 白底蓝描边胶囊，配色沿用原 `.is-active` 的底色。
- 激活项本身的静态底色（`background` + `box-shadow`）从 aurora / calm 两处 `.is-active` 移除，改由指示器承载——否则指示器滑过时底色会和静态底叠成两层。文字色与字重保留。
- 极光补上**左侧彩色索引条**（`::before`，3px，`--glow-1 → --glow-2` 渐变），对齐纸面已有的实现，消除两主题不对称。
- 降级：`prefers-reduced-motion` 下 `transition: none`（选择器带 `[data-ready]` 才压得住过渡声明）。

> 与原计划的两处偏差：
> 1. **用实测矩形而非「索引 × 行高」**。导航在 ≤640px 会翻成横排，写死行高会错位；实测 `offsetLeft/offsetWidth` 后横排布局同样跟得上，行高/内边距后续调整也不会失效。resize 时会重新测量。
> 2. **过渡开关比几何晚一帧**（`requestAnimationFrame` 后置 `data-ready`）。否则首次测量会让胶囊从 0×0「长」出来；现在首帧几何直接落位，只有一次淡入。

### D2 电池模式降动效

- `src/shared/types.ts` 新增 `PowerMode = 'battery' | 'ac'`。
- **主进程**（`electron/main.ts`）：`powerMonitor.on('on-battery' / 'on-ac')` 更新模块级 `powerMode` 并向所有窗口广播 `power-mode`；新增 `get-power-mode` IPC 供后开的窗口取当前值。初始态用 `powerMonitor.isOnBatteryPower()` 探测（该 API 在部分平台可能缺失，做了 `typeof` 守卫，缺失时按接电源处理，不误伤）。
- **preload**：`getPowerMode()` / `onPowerMode(cb)`。
- **渲染层**（新增 `src/renderer/powerMode.ts`）：`startPowerModeSync()` 在两个入口 `ReactDOM.render` **之前**执行，把模式写到 `<body data-power="…">`——越早落属性，电池模式下越少一拍全速动效。
- **CSS**（`[data-power='battery']`）：与 `motion-muted` 完全同构，`--glass-speed: 2.4` 放慢球体内部液态流动；`animation: none` 关停 `orbBreathe`、`glassShine`（概览卡 / 指标卡 / 用量块 / 分区头 / 用量行 共 5 处）、`pageAuroraDrift`（悬浮球面板 + 设置页）、`glowOrbit`（面板流光边框 + 卡片边框）、三色灯轮播。
- **dev 调试口**：`installPowerModeDebugHook()` 在 `import.meta.env.DEV` 下挂 `window.__setPowerMode('battery' | 'ac')`——台式机没有电池，powerMonitor 永不广播，靠它手动验证。生产构建下整段被 tree-shake。

> 比计划多收了两处持续动画：`.settings-page::after`（`pageSheenSweep`）与 `.set-card::after`（`cardGlassDrift`）。二者都是大面积渐变的长周期动画，是设置窗的主要 GPU 开销，不关掉的话「电池模式」在设置窗基本无感。
> 未关停：`.floating-ball__orb-ring-glow` 的 `orbGlowPulse`（纯 opacity，开销低，保留能维持「活着」的观感）。

## 影响范围
- 两窗 × 双主题：噪点仅极光；电池模式两主题都生效（纸面本就无持续动效，命中时基本无感）。
- 设置窗：导航指示器替换了激活态的静态底色，是本次**唯一需要重点肉眼回归的视觉改动**；大屏（≥1280px）内容宽度 720 → 860。
- 新增一个 IPC（`get-power-mode`）与一个广播频道（`power-mode`），不改变既有通信契约。
