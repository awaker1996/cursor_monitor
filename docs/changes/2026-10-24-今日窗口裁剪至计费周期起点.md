## 变更摘要
- 今日事件查询窗口的起点由「本地零点」改为 `max(本地零点, billingCycleStart)`（`getTodayRangeMs`），使今日窗口恒为计费周期窗口的子集；周期起点缺失、非法或位于未来时退回本地零点
- `buildUsageEventsResponse` 不再对空事件返回 `null`，恒返回响应对象，用 `eventsComplete` 区分「样本完整且确实没有用量」（今日口径为 0）与「取数失败 / 分页截断」（今日口径不可得）；`fetchUsageEvents` 返回类型同步由 `RawUsageEventsResponse | null` 改为 `RawUsageEventsResponse`
- 新增 `scripts/verify-today-range.ts` 回归脚本，覆盖窗口裁剪、边界保护、窗口内含关系与空样本语义；`tsconfig.verify.json` 纳入该脚本
- 取数段顺势清理：`fetchUsageEvents` 不再返回 `null` 后，`CookieProvider.fetch` 不再预声明 `todayEvents` / `cycleEvents` / `aggregatedUsage` 三个 `unknown | null` 变量并赋 `null` 初值，改为在 `try` 内以 `const` 直接解构 `Promise.all` 结果，`return` 移入 `try`；`finally` 仍先于返回执行，三处 `clearTimeout` 的清理时机不变。`fetchAggregatedUsage` 的 `null` 保留（表示聚合端点不可用、需回退事件聚合，语义真实）

## 影响范围
- **根因**：额度在计费周期起点重置，跨过该起点的「今日」用量属于上一个周期。若把它算进今日，而周期侧暂时还没有可归属用量（周期内只有被剔除的 `grok-bot-*`），今日/周期的份额就失去分母，`todayUsedPercent` 只能返回 `null`；收起态 `cursorCollapsedChips` 对 `percent == null` 的桶直接 `continue` 丢弃，于是「今日 Cursor」小条整根消失，只剩「今日 Other」
- **实测**：真实账号在周期重置后 3.4 小时，周期内 30 条事件全部为 `grok-bot-default` / `grok-bot-automation`，`autoTodayTokens` 为 1,403,344、`autoTodayUsed` 为 $1.18，但 `autoTodayUsedPercent` 为 `null`，卡片只显示「今日 Other 0%」
- 裁剪后真实链路复核：收起态恢复为「今日 Cursor 0% | 今日 Other 0%」两根条
- 裁剪后「今日」不再包含上个周期已结算的用量，属于口径修正；周期内用量（如今日 0.00%）与 `usage-summary` 的 `plan` 汇总一致
- 空样本语义修正后，周期刚重置、周期内确实无用量时今日显示 0 而不是「—」，与 README 第 6 章「null 与 0 不可混同」一致
- 周期指标、Included Usage、订阅链路不受影响
- `get-aggregated-usage-events` 保持原样（本次仅诊断，未改代码）：服务端已剔除 `grok-bot-*`，窗口内只剩该类调用时响应体只含 `startDate` 而不含 `aggregations`，属上游行为而非契约变更
