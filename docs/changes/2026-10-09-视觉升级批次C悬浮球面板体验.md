## 变更摘要

背景：批次 B 把语义色 / 动效 / 圆角字号收成令牌后，本批次做「体验层」——面板入场的节奏感、视图切换的连贯性、用量明细的可读性、orb 数字的过渡，以及折叠态的信息补全。全部建立在 B 批次的令牌之上，无新增硬编码色值与时长。

### 修复：批次 B 遗留的动效令牌自引用（fix）

批次 B 的批量替换把 `cubic-bezier(...)` 字面量**连同令牌自身的定义行**一起替换掉了，导致：

```
--ease-out:    var(--ease-out);      ← 自引用
--ease-spring: var(--ease-spring);
--ease-smooth: var(--ease-smooth);
```

按 CSS 规范，自引用的自定义属性在计算值阶段即失效（invalid at computed-value time），于是所有 `var(--ease-*)` 的声明整条失效——受影响的有：进度环 `stroke-dashoffset` 过渡、球心 `cx/cy/r` 过渡、视图切换胶囊 `switchThumbShine` 的回弹 transition、面板显隐过渡等 13 处。**这些动效在批次 B 之后实际是静默失效的。**

已修正为真实曲线值：`--ease-out: cubic-bezier(0.22, 1, 0.36, 1)`、`--ease-spring: cubic-bezier(0.34, 1.4, 0.5, 1)`、`--ease-smooth: cubic-bezier(0.4, 0, 0.2, 1)`。

补充扫描确认：全仓仅剩一处自引用 `.floating-ball__orb--motion-muted { --orb-glow-color: color-mix(in srgb, var(--orb-glow-color) 55%, transparent) }`，为**改动前既有**写法，同样会失效（数据陈旧/退避/暂停时 orb 光晕整条 `box-shadow` 失效）。因属既有行为且涉及视觉表现，本次未擅自改动，留待确认。

### C1 指标卡入场 stagger

- `MetricRow` 新增 `index` / `stagger` 两个可选 props；`stagger` 为真时注入 `style={{ '--stagger-i': index }}` 并挂 `.metric-card--stagger`。
- App 侧只在 `panelAnimOpen === true`（面板展开动画真正起步后）才传 `stagger`，避免面板尚未挂载时动画就跑完。
- CSS：`animation: staggerFadeUp 0.3s var(--ease-out) backwards` + `animation-delay: calc(var(--stagger-i, 0) * 40ms)`，四张卡 0/40/80/120ms 依次上浮淡入（6px 位移）。

**填充模式刻意用 `backwards` 而非 `both`**：`both` 会在动画结束后永久保留 `transform: none`，把 `.metric-card:hover` 的位移压掉；`backwards` 只在延迟期间吃到 `from` 初态（避免先闪现再动），结束后交还给常规样式。

### C2 概览 ⇄ 用量切换过渡

- 面板 body 内新增一层 `.panel-view-pane`，`key={panelView}`——切换视图即重挂载，触发一次淡入。
- CSS 让该层完整镜像原 body 的 flex 链（`flex: 1; min-height: 0; display: flex; flex-direction: column`），因此概览的 402px 配平、指标卡等分填满、用量区的自身滚动**全部保持原样**。
- 动画 `panelViewFadeIn`：opacity 0→1 + `translateY(4px)→0`，只用 transform/opacity，不改布局终态。时长取 `var(--dur-fast)`（0.16s），与胶囊 0.34s 的滑移形成「胶囊先动、内容跟上」的节奏。

> 与原计划的一处偏差：计划写 0.12s，实际取现有时长档 `--dur-fast`（0.16s）。0.12s 不在批次 B 建立的时长档位内，为不再引入孤立项，就近并入 fast 档。

### C3 用量行 mini 占比条

- `src/shared/format.ts`：`IncludedUsageModelRow` 新增 `shareValue: number`，在 `buildIncludedUsageDisplay` 构造时计算——**基准是本分区内 token 量最大的模型**（而非分区总量），因此占比条表达的是「模型之间的量级差异」，与右侧 Usage 列（对套餐额度的消耗）语义互补、不重复。
- 结构：每行 `.included-usage__entry` 内追加 `.included-usage__entry-share`（2px 轨道）与 `.included-usage__entry-share-fill`（填充条，`width` 走 `var(--dur-base)` 过渡）。
- **轨道用绝对定位贴在行底**（`left/right: 8px; bottom: 3px`），零布局增量——面板高度是精确配平的，不能让 2px 轨道把 N 行逐一撑高。
- 配色直接吃批次 B 的语义色：api 分区 `var(--ok-bg)`、auto 分区 `var(--info-bg)`，极光 / 纸面两套自动切换，无需写 calm 覆盖；仅轨道底色在 calm 下补一条 `rgba(15,23,42,.09)`（默认的白色半透明在纸面底上不可见）。

### C4 orb 数字 count-up

- 新增 `src/renderer/useCountUp.ts`：`useCountUp(target, duration = 300)`，rAF + easeOutCubic 补间 `orbSummary.percentValue`。
  - 首次挂载不做 0→N 动画（`useState` 初值即 target），避免每次开窗都跳一遍；只在**数据真的变化**时补间。
  - 补间途中 target 再次变化，从**当前显示值**接着补，不回跳。
  - `prefers-reduced-motion: reduce` 或 `target === null` 直接落终值。
- 展示规则与原来一致（`Math.round` 后拼 `%`），无数据时仍显示 `--`。
- pulse 机制：原 `key={orbSummary.value}` 改为 `key={orbPulseKey}`（取整后的目标值）。补间过程中 key 稳定，因此 `orbValuePulse` 只在目标值真正变化时触发一次，不会每帧重放。

> 与原计划的一处偏差：计划「补间终值时触发一次 pulse」，实际落在「目标值变化时触发一次」。数字本身已在补间中滚动，起手即给出一次脉冲反馈更即时，且省掉一个完成回调定时器；与改动前的 pulse 时机基本一致。

### C5 折叠态 hover tooltip 复活

- 复用现成的 `.floating-ball__tooltip` / `__tooltip-line`（含 calm 纸面适配），此前全仓无引用、属死样式。
- 渲染在 `.floating-ball__orb-wrap` 内（该元素已是 `position: relative`），气泡本体样式沿用既有定位（`right: 0; bottom: calc(100% + 8px)`），窗口 300×448 有足够空间向左上展开。
- 触发条件：`orbHovered && !expanded && !isDragging && !dockedEdge`——展开态、拖拽中、贴边半隐态一律不显示。
- 四行内容全部取自现成计算结果，无新增数据源：状态标签（`healthLabel`）／今日 Cursor Models／今日 Other Models／来源 · 上次刷新时间（`buildDashboardSummary`）。
- 补 `orbTooltipIn` 淡入（3px 位移，`--dur-fast`）。

### 降级
