# 用量分区头展示完整池名（Cursor Models / Other Models）

日期：2026-10-21
类型：fix, style, refactor
涉及文件：`src/renderer/components/IncludedUsageTable.tsx`、`src/renderer/styles.css`、`README.md`

## 背景

悬浮球「用量」视图两个分区头（Cursor / Other）是「实心徽标 + 名称 + 右侧统计值」三段：

```tsx
<span className="included-usage__badge">{accent === 'api' ? 'Other' : 'Cursor'}</span>
{category.label !== categoryBadge(accent) && <span className="included-usage__section-label">{category.label}</span>}
```

`categoryBadge()` 返回缩写（`Cursor` / `Other`），与完整 label（`Cursor Models` / `Other Models`）不相等，因此**两区都是「徽标 + 全名」并排**——徽标把名称首词又说了一遍，白占约 46px（含间距）。叠加三个因素后，Other 分区先崩：

1. 名称是 `white-space: nowrap` + `text-overflow: ellipsis`，放不下就只剩省略号；
2. 右侧「总量 + 占比」不压缩（`flex-shrink: 0` + `margin-left: auto`）；
3. Other 的统计值更宽：`2727.3万 / 100.00%`（7 位 token）vs Cursor 的 `4.2亿 / 60.85%`（4 位 token）。

面板内容区仅 276px，于是同一行里 Cursor 的 `Cursor Models` 还完整，Other 的 `Other Models` 已被挤成 `Other Mod…`——即用户截图中的落差。

## 改动

### 1. 统一分区头结构：只保留「池名 + 统计值」

`IncludedUsageTable.tsx` 删除 `categoryBadge()` 与 `included-usage__badge` 节点，`categoryBadge` 不再存在；头部改为：

```tsx
<header className="included-usage__section-head" title={title}>
  <span className="included-usage__section-label">{title}</span>
  <span className="included-usage__section-stats">…</span>
</header>
```

- `categoryTitle()` 兜底：label 仍是缩写 `Other` 时映射到官方全名 `OTHER_MODELS_LABEL`（`Other Models`），避免历史快照出现歧义；正常数据（normalizer 已写入全名）原样透传。
- `section` 的 `aria-label` 与头部 `title` 都用完整池名，Hover 可读全称，屏幕阅读器分区名不变。

### 2. 池名从「nowrap + 省略号」改为「整词换行 + 极端情况才省略」

| 属性 | 改前 | 改后 |
|---|---|---|
| `white-space` | `nowrap` | `normal` |
| `overflow-wrap` | — | `anywhere` |
| `flex` | `1` | `1 1 auto` |
| 字号 / 字重 | `--fs-mini` / 600 | `--fs-caption` / 700 |

窄一分区头时优先折成两行（`Other` / `Models` 仍可完整阅读），实在放不下才出省略号；不设 `margin-left: auto`，池名不会被自动外边距挤成窄条。

### 3. 头部与模型行共用左右规约（对齐修正）

- `padding` 由 `5px 6px` 改为 `5px 8px`，与 `.included-usage__entry` 的左内边距一致；
- 头部补 `border: 1px solid transparent`，抵消行的 1px 实边框，使**池名与模型名同一竖线、统计值与行的 Usage 列右缘重合**；
- `align-items` 由 `center` 改为 `baseline`，与行内基线对齐一致。

实测（276px 面板、2× 截图，量测 `getBoundingClientRect`）：两区 `labelLeft = nameLeft = 40`、`statUsageRight = rowUsageRight = 260`、`blockOverflow = 0`、两区池名均 `truncated = false` 且单行（h=14px）。

### 4. 主题适配

- 极光玻璃：徽标色块删除后，分区识别交给「头部底色 + 统计值颜色」（api 绿 / auto 蓝），与模型行同族，不再需要 `--ok-fg` / `--info-fg` 之外的硬编码徽标色（原来的 `#34d399` / `#60a5fa` 实心块一并移除）；
- 清爽纸面：原 `.included-usage__badge` 两条 calm 覆盖（绿/蓝实底 + 白字）改为池名文字色——api 用 `var(--calm-ok)`、auto 用 `var(--calm-accent)`，浅底上仍能一眼分区；原先 `__section-label` 的单一 `--calm-ink-2` 覆盖被这两条替代。

## 影响范围

- 仅悬浮球「用量」视图的分区头；模型行、mini 占比条、概览视图、设置窗口、托盘均未改动。
- 数据契约不变：仍消费 `IncludedUsageCategoryRow.label`，无 IPC / 快照 / 持久化变更。
- 头部高度增加 2px（1px 透明边框 ×2），分组块因此每块高 2px；`.included-usage__body` 本身纵向滚动，402px 概览配平链不受影响（概览视图不渲染该组件）。

## 验证

- `npm run typecheck` 通过（electron + renderer 两个 tsconfig）。
- `npm run build` 通过；产物 CSS 中 `included-usage__badge` 计数为 0，`section-head` 的 `border:1px solid transparent` 命中 1 条，`__section-label` 规则 3 条（基础 + 两主题色）。
- 用真实 DOM 链（窗口 300×448 → 面板框 276×402 → panel-body → included-usage）在 Chromium 内核下渲染量测：两区池名完整、单行、无横向溢出；池名与模型名竖线、Usage 列右缘均重合（见上文数字）。
- 双主题 2× 截图确认：极光下两区池名白色 11px/700，纸面下分别为品牌蓝 / 品牌绿，右侧 `4.2亿 60.85%`、`2727.3万 100.00%` 完整显示。
