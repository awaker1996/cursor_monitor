# 修复打包时下载 Electron 超时导致的构建失败

## 日期
2026-10-21

## 类型
fix

## 关联文件
- `package.json`
- `README.md`
- `docs/changes/README.md`

## 变更摘要
- `build.electronDist` 指向 `node_modules/electron/dist`，`electron-builder` 直接复用 `npm install` 已装好的 Electron，不再下载 `electron-v28.3.3-win32-x64.zip`
- README「打包与发布」新增「Electron 与打包工具链的来源」小节，说明 `electronDist` 与 NSIS 工具链的一次性下载
- README「常见问题」新增该报错的排查行：真因是工具链下载失败，而非产物被占用

## 影响范围
- **报错表象与真因不同**：`ERR_ELECTRON_BUILDER_CANNOT_EXECUTE` 在本仓库有两种成因——输出目录被编辑器占用（`scripts/dist.mjs` 已规避），以及 `app-builder.exe unpack-electron` 下载 Electron 包失败。后者需要在日志里找到 `• spawning ... unpack-electron` 之后的 `⨯ Get "https://github.com/electron/..."` 才能确认
- `electron-builder` 的 Electron 缓存（`%LOCALAPPDATA%\electron-builder\Cache\electron`）缺失时，它不会回退到 `node_modules`，而是无条件重新下载；配置 `electronDist` 后该下载路径被完全跳过
- NSIS 工具链（`nsis`、`nsis-resources`）仍需首次打包时下载一次到 `%LOCALAPPDATA%\electron-builder\Cache`；GitHub 不可达时用 `ELECTRON_BUILDER_BINARIES_MIRROR` 重试一次即可，之后离线可用
- 关闭代码签名（`signAndEditExecutable: false`）使其不需要 `winCodeSign`，缓存只有两个目录
- `electronDist` 只影响 Electron 二进制来源，`files` / `electronLanguages` / `compression` 等打包输入与产物结构不变

## 验证
- 复现：`node scripts/dist.mjs` 在 `unpack-electron` 阶段报 `Get "https://github.com/electron/electron/releases/download/v28.3.3/electron-v28.3.3-win32-x64.zip" ... 连接超时`，退出码 1
- 修复后执行 `npm run dist`（未设置任何环境变量）通过：`copying Electron source=node_modules\electron\dist` 表明走本地复用，日志无下载请求
- 产物正常：`release/Cursor Token Monitor Setup 1.0.0.exe`（67.5 MB）、`release/Cursor Token Monitor 1.0.0.exe`（67.2 MB）、`blockmap`、`latest.yml`、`release/win-unpacked`（locales 仅 `en-US.pak` / `zh-CN.pak`，`resources/app.asar` 约 2 MB，exe 已更名为 `Cursor Token Monitor.exe`）
- 版本一致性：`node_modules/electron/dist/version` 为 `28.3.3`，与 devDependencies 的 `electron@^28.3.3` 一致
