# 系统代理接入与「缓存数据」标记粒度修复

- 日期：2026-10-31
- 类型：fix
- 关联文件：src/core/httpClient.ts（新增）、src/core/providers/CookieProvider.ts、src/core/snapshotMerge.ts、src/shared/types.ts、src/shared/format.ts、src/renderer/App.tsx、src/renderer/styles.css、scripts/verify-today-percent.ts、README.md

## 背景与根因

现象：弹窗状态 pill 长期显示「缓存数据」，周期 token 明细停在旧值（512.7K），日志里反复出现

```
[CookieProvider] Network error, retrying request { url: 'https://www.cursor.com/...', error: 'fetch failed' }
[CookieProvider] Aggregated usage endpoint returned unusable response { status: 200, error: null }
```

排查结论分三层：

1. **应用没有走系统代理**。`CookieProvider` 用的是 Node/undici 的全局 `fetch`，它不读系统代理设置；本机 `ProxyEnable=1`、`ProxyServer=127.0.0.1:7890`，而应用仍在直连 `cursor.com`。直连链路上 TLS 握手会被间歇性重置（项目 2026-07-25 已实测同样现象），报错形态是 `fetch failed`。
2. **登录重定向被 follow 成了 200 HTML**。未授权时 `get-aggregated-usage-events` 返回 **307 指向 WorkOS 登录页**，而 `fetch` 默认自动跟随，最终拿到 200 的登录页 HTML，旧代码只看到「200 但 body 里没有 aggregations、error 为 null」，日志完全看不出真实原因。实测（无 Cookie 请求，经代理）：summary → 401 JSON，aggregated POST → 307 `api.workos.com/...`。
3. **明细回填直接污染整颗快照的 `stale`**。`mergeCycleTokensFromCache` 一旦用上轮值补齐周期 token，就把 `stale` 置真，状态 pill 立刻变「缓存数据」并常驻到下一次明细成功为止；实际上百分比等主指标都是新鲜的。

## 变更摘要

- 新增 `src/core/httpClient.ts`：
  - `httpRequest()` 统一出口：探测到系统代理时对公网 https 走 CONNECT 隧道（`CONNECT host:443` → 隧道上 TLS，ALPN 固定 `http/1.1`），否则退回原生 `fetch`（脚本、无代理环境行为不变）
  - 代理探测优先级：环境变量（`HTTPS_PROXY` 等）→ Chromium `session.resolveProxy()`（跟随系统设置、支持 PAC）→ Windows 注册表 `ProxyServer`；结果缓存，`resetProxyCache()` 可重探测；失败一律退回直连
  - 请求不再自动跟随重定向（两条链路一致），避免把登录页当成正常响应；POST 显式补 `Content-Length`，不退化成 chunked
- `CookieProvider`：
  - 三个 dashboard 请求改走 `httpRequest`
  - 事件 / 聚合接口失败日志补充 `contentType`、`redirect`（识别重定向到 WorkOS → 直接写「Cookie 可能已过期」）、`bodyPreview`（去空白截断 160 字符）
  - 事件接口 200 但结构不是事件列表（登录页 HTML / 空对象）时按失败处理，不再静默当成「今天没用量」
  - 聚合接口 body 增加 `userId` 变体（有 userId 时先带、失败再退回老形态）
- `snapshotMerge.mergeCycleTokensFromCache`：不再置 `stale`，改为置 `tokenDetailCached: true`；`TokenSnapshot` 新增该可选字段
- 渲染层：`DashboardSummary` 新增 `detailCached`，概览 token 明细后追加「缓存」小角标（带 title 提示）；状态 pill 只在整轮失败 / 磁盘缓存 / 退避时才是「缓存数据」
- README：补充代理行为、明细缓存角标语义与两条排查项

## 影响范围

- Cookie 链路的全部 `cursor.com` 请求（summary / events / aggregated）；有代理时新增一次 CONNECT 建连开销，失败重试次数不变
- 状态 pill 与悬浮球「静音动效」判定：明细回填不再触发黄色状态
- 今日指标回填仍保留 `stale`（今日数值过期比明细过期更需要提示，本次不动）
- 官方链路、订阅链路（DeepSeek / CommandCode / GrokBot）本次未改

## 验证

- `npm run typecheck` 通过
- `scripts/verify-today-percent.ts`、`scripts/verify-included-usage.ts`、`scripts/verify-cookie-summary.ts` 全部通过（`cycle merge marks token detail cached` / `cycle merge does not latch stale` 为新增断言）
- 隧道链路实测（本地临时代理 + 真实 `cursor.com`）：GET summary 返回 401 JSON、POST aggregated 返回 307 WorkOS 重定向，`content-type` 与重定向头均可读到，证明 CONNECT → TLS → HTTP 链路与 `Content-Length` 处理正常
- 真实 Clash 代理（`127.0.0.1:7890`）下同样得到 401 / 307，与直连（401 / 401）行为对比确认代理生效
