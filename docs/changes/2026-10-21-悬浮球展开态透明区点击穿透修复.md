# 悬浮球展开态透明区点击穿透修复

- 日期：2026-10-21
- 类型：fix
- 关联文件：`src/renderer/App.tsx`

## 现象

点击悬浮球展开弹窗后，弹窗与球体以外的区域会吞掉鼠标点击：桌面图标、被浮窗覆盖的其他窗口、以及通过面板打开的设置窗口都点不动；收起弹窗后恢复正常。

## 根因

1. 悬浮球窗口物理尺寸固定为 `300×548`（`electron/windows/floatingBall.ts` 的 `ORB_EXPANDED_HEIGHT`），而面板只有 `276×402`、球体 `56×56`，其余都是透明像素：
   - 面板左右各 12px 留白、顶部约 34px、底部 12px；
   - 球体左侧约 `210×100` 的空白区；
   - 面板底边与球体顶部之间约 30px 的间隙。
2. `src/renderer/App.tsx` 的 `setMousePassthrough()` 把 `expandedRef.current` 与 `draggingRef.current` 并列短路：

   ```tsx
   if (draggingRef.current || expandedRef.current) {
     window.electronAPI.setIgnoreMouseEvents(false);
     return;
   }
   ```

   同时负责命中检测的 `useEffect` 在 `expanded` 为真时直接 `return`：

   ```tsx
   if (expanded) {
     window.electronAPI.setIgnoreMouseEvents(false);
     mousePassthroughRef.current = false;
     return;
   }
   ```

3. 结果是展开态整窗 `ignoreMouseEvents = false`。Windows 对透明窗口的透明像素同样做命中测试，于是 `300×548` 矩形内的点击全部被浮窗吃掉，不会落到下层窗口。
4. 折叠态没有这个问题：折叠态仍走 `document.elementFromPoint` + `INTERACTIVE_SELECTOR` 判定，只有球体/提示区可交互，透明区已开启穿透。

> 历史背景：2026-07-06 的「缓存报错与收起闪烁修复」为修「穿透导致 orb 点不中」，曾以「展开态强制关闭穿透」兜底。本次改为展开态也按命中区域判定，不再整窗可命中。

## 改动

1. `setMousePassthrough()` 只保留拖拽短路：拖拽期间整窗保持可命中，保证鼠标移出窗口后仍能收到 `mouseup` 收尾；展开态不再强制可命中。
2. 穿透检测 `useEffect` 去掉 `expanded` 的提前返回：
   - 展开瞬间仍先 `setIgnoreMouseEvents(false)`，保证面板进场动画期间按钮可点；
   - 随后每次转发的 `mousemove` 与 80ms 轮询都按 `elementFromPoint` 判定，命中 `.floating-ball__orb-wrap / .floating-ball__orb / .floating-ball__panel-frame / .floating-ball__panel` 才关闭穿透，其余透明区开启穿透。
3. 贴边态（`dockedEdge`）逻辑保持不变：半隐球有一部分落在屏幕外，整窗保持可命中，避免 peek 条点不中。

## 影响范围

- 仅悬浮球窗口的鼠标穿透判定；窗口尺寸/位置、面板布局、贴边逻辑、拖拽位移、数据轮询均未改动。
- 展开态下面板与球体之外的像素恢复点击穿透，包含左侧留白、球体左侧空白、面板与球体间隙、圆角外沿等。
- 穿透区域内的点击不会传给渲染层，因此当前仍无「点击面板外部自动收起」语义（改动前也没有；如需该行为需另加主进程焦点/全局鼠标监听）。
- 贴边态仍是整窗可命中（历史兼容选择），若后续也要求贴边留白穿透，需要单独验证 peek 命中。

## 验证

### 无窗口 Electron 实测（假光标驱动轮询）

用 Electron 以 `show: false` + `opacity: 0` 加载构建后的 `dist/index.html`，preload 走真实 `dist-electron/preload.js`；主进程 stub 数据 IPC 并记录 `set-ignore-mouse-events` 调用，用 stub 的 `get-cursor-in-window` 驱动渲染层 80ms 轮询，再用 DOM 事件模拟点击球展开。验证窗口本身始终 `setIgnoreMouseEvents(true)`，不会干扰桌面。

| 场景 | 期望 | 修复后 | 修复前（对照） |
|---|---|---|---|
| 折叠态左上留白 (5,5) | 穿透 | true | true |
| 折叠态球心 | 不穿透 | false | false |
| 展开态左上留白 (5,5) | 穿透 | true | **false** |
| 展开态面板中心 | 不穿透 | false | false |
| 展开态左上留白（再次） | 穿透 | true | **false** |
| 展开态球心 | 不穿透 | false | false |
| 展开态球左下留白 (20,540) | 穿透 | true | **false** |
| 展开态面板中心（再次） | 不穿透 | false | false |

- 修复后 8/8 通过，渲染层 `pageErrors = 0`；实测展开态面板矩形 `276×402 @ (14,28)`、球体 `56×56 @ (212,460)`。
- 对照实验：把 `App.tsx` 回退到 HEAD 重新构建后，展开态 3 个透明区步骤全部判为「不穿透」——说明本 bug 可稳定复现，且折叠态一直正常，与用户描述一致。
- 静态核对：`INTERACTIVE_SELECTOR` 覆盖球体包装、球体、面板外框、面板本体；`.floating-ball` 根节点不在其中，透明留白处 `closest()` 返回 `null` → 开启穿透。

### 常规检查

- `npm run typecheck` 通过（electron + renderer 两个 tsconfig）。
- `npm run build` 通过（renderer 与 electron 产物均正常输出）。
